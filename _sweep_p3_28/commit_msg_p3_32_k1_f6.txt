CONTEXT — THIRD LEAK ROOT CAUSE
The payroll schedule lives in two snapshots: the SQL
`payroll_headcount` column (canonical, written by Handler C apply
chain at every persist) AND `model_input.derived_driver_runtime[
expenses::Payroll].payroll_headcount` (snapshot updated only when
apply_payroll_headcount_payload_to_model_input is called).

The convergence runner persists a new schedule (e.g. Registered
Nurses benefits_pct=0.25 / Q1=106928) to SQL atomically. BUT the
orchestrator's _run_post_cascade_completion was called with a
stale local payroll_headcount variable (schedule from before
convergence: benefits_pct=0.22 / Q1=106192). The orchestrator
pre-finalize persist then wrote model_input.expenses.Payroll.values
derived from the stale schedule over the canonical SQL state.

Empirical evidence from CareFirst draft 0caeb5ad5d0843a6b4f0e52ba0cf7d5f:
  SQL payroll_headcount column:
      RN row Q5 benefits_pct = 0.25, quarter_totals[Q5] = 110138
  model_input.derived_driver_runtime[expenses::Payroll].payroll_headcount:
      RN row Q5 benefits_pct = 0.22, quarter_totals[Q5] = 109380
  model_input.expenses::Payroll.values[5] = 109380
  -> 758 dollars per quarter Payroll divergence between Handler C
     canonical schedule and the model_input the workbook reads.
  -> V-4 verifier surfaced 15362 dollars Cash Q20 divergence on
     CareFirst (and previously 44929 dollars Cash Q20 on Caring Hands).

Verified payroll is the ONLY lever surface with this class of
embedded-snapshot bug. Other expense / balance_sheet / revenue rows
store values directly in model_input.values without a separate SQL
column or embedded schedule snapshot.

F6 FIX SHAPE — TWO PARTS

PART 1 — Re-sync at start of _run_post_cascade_completion
(orchestrator.py:~1710-1820, ~120 LOC):
  - Re-read canonical payroll_headcount from SQL.
  - If quarter_totals tuple differs from local variable, call
    apply_payroll_schedule_to_state (the canonical P3.26 Commit 2
    apply primitive) to refresh model_input + finmo through the
    Mirror Flavor 1 apply chain (zero-tolerance assertions).
  - Update local payroll_headcount, final_model_input_json,
    final_finmo_json, next_result to canonical state.
  - completion_trace[payroll_state_resync] records outcome
    (in_sync / completed / canonical_empty / apply_failed /
    resync_lookup_failed).

PART 2 — Pre-finalize three-surface invariant
(orchestrator.py:~2860-2965, ~100 LOC):
  - BEFORE the pre-finalize persist try/except (kept outside so the
    fail-fast surfaces clearly), assert per-quarter equivalence
    (with 1 dollar int-rounding tolerance) across:
      (a) payroll_headcount.quarter_totals.payroll
      (b) model_input.expenses.Payroll.values[1..N]
      (c) model_input.derived_driver_runtime[expenses::Payroll].
          payroll_headcount.quarter_totals.payroll
  - On disagreement, raise
    PostIntakePreconditionFailed(operation=
    pre_finalize_persist_payroll_three_surface_invariant_violation)
    naming all three surfaces, the per-quarter deltas, and a
    guidance line pointing operators at the intervening stage that
    must have bypassed apply_payroll_schedule_to_state.
