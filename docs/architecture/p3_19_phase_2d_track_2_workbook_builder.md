## A. Confirmation paragraph (in my own words)

The workbook is generated by Python code that writes Excel formula STRINGS into cells. When the Python code interpolates a numeric literal into the formula string, that literal becomes a permanent part of the formula in every quarter — it does not pick up changes to other cells in the workbook. To fix this, the Python code must be changed to write a cell reference into the formula string instead of a literal value. The fix happens in the workbook builder code, NOT in any post-intake data writer.

Concretely:

- A cell-reference formula like `f"=...*{local_ref(interest_rate, col)}"` becomes Excel `=...*D12` when written into column D. If the user edits cell D12 in Excel (or the model_input is re-exported with a different value into D12), the formula re-evaluates against the new D12 value.
- A literal-interpolation formula like `f"=...*{rate_cell_value}"` becomes Excel `=...*0.025625` when `rate_cell_value` is the Python float `0.025625`. The string `0.025625` is BAKED INTO the Excel formula. Excel has no idea this number originated from any cell. If the user edits the Interest Rate cell in Excel, this formula does NOT re-evaluate.

Both produce the SAME numerical answer at workbook-generation time IF the Python value matches what the cell would hold. The difference shows up when (a) a user edits in Excel, (b) a workbook regeneration uses a different source value, or (c) future Python changes shift the writer site but not the consumer formula. The cell-reference pattern is the safe one; the literal pattern is the brittle one.

The fix for any of these is workbook-builder-only: change the Python formula string from `f"...*{python_literal}"` to `f"...*{local_ref(target_row, col)}"`. No data layer needs to change.

## C. Specific hardcoded literals in lease formulas

### C1. Row 22 (Lease Interest Expense) — file:line 519-520

```python
rate_cell_value = interest_rate_values_lease[idx] if idx < len(interest_rate_values_lease) else 0
ws.cell(lease_interest, col, value=0 if idx == 0 else f"={local_ref(lease_open, col)}*{rate_cell_value}")
```

- `interest_rate_values_lease` is set at line 491 by reading the **same** model_input Interest Rate row that the debt section reads at line 440 (`expense_by_label.get("Interest Rate")`).
- `rate_cell_value` becomes a Python float (e.g. `0.025625` post-Phase 2 or `0.1025` pre-Phase 2).
- The resulting Excel formula in cell D22 is `=D18*0.025625` (Q1 example). The literal 0.025625 is baked in.
- **Where the literal is interpolated:** schedule_sheets.py line 520, the f-string `f"={local_ref(lease_open, col)}*{rate_cell_value}"`. The `{rate_cell_value}` part is the literal interpolation.
- **What it could be instead:** `f"={local_ref(lease_open, col)}*{local_ref(interest_rate, col)}"` — referencing the Interest Rate row (variable name `interest_rate` from line 435, set as a cell on this same sheet at line 453). The cell-ref pattern would mirror the debt interest formula at line 454 exactly.

### C2. Row 25 (Lease Asset Depreciation) — file:line 506+510 / 523

```python
lease_seed_value = number(schedules.get("lease_opening_balance_seed")) or 0
# ...
per_quarter_dep_formula = f"({lease_seed_value if lease_seed_value else 0}/20)"
# ...
ws.cell(lease_dep, col, value=0 if idx == 0 else f"=MIN({per_quarter_dep_formula},{local_ref(rou_open, col)})")
```

- `lease_seed_value` is the Python value of the lease opening balance seed (e.g. `54000` for the ExpressLogix lease scenario).
- `per_quarter_dep_formula` is a STRING like `"(54000/20)"` (Python literal interpolation).
- The resulting Excel formula in cell D25 is `=MIN((54000/20),D24)` (Q1 example). The literal 54000 is baked in.
- **Where the literal is interpolated:** schedule_sheets.py line 510, the f-string `f"({lease_seed_value if lease_seed_value else 0}/20)"`. The `{lease_seed_value}` part is the literal interpolation.
- **What it could be instead:** `f"({local_ref(lease_open, PERIOD_START_COL)}/20)"` — referencing the Lease Opening Balance Q0 cell (column C, the Q0 column). The Q0 cell carries the same seed value (line 513 wrote it as a literal at Q0).

## D. Why does the debt interest formula use a cell reference but the lease interest formula uses a literal?

The two formulas live in the same function (`build_debt_schedule_sheet`), use the same input source (`expense_by_label.get("Interest Rate")` — lines 440 and 491), and could trivially use the same pattern. The difference is purely a coding-style choice by whoever wrote each section:

- **Debt section** (older, written before P3.16): the author kept the Interest Rate row visible on the Debt Schedule sheet (row 12), wrote rate values into it as plain values (line 453), and used `local_ref(interest_rate, col)` in the Interest Expense formula (line 454). Result: the Excel formula references the in-sheet Interest Rate cell, which is itself editable.

- **Capital lease section** (added in P3.16, commit 7b8928b — my work): I read the same Interest Rate row into a Python list (`interest_rate_values_lease`, line 491) and interpolated each per-quarter value directly into the formula string (line 520). I did NOT use `local_ref(interest_rate, col)` even though `interest_rate` (the in-sheet row variable from line 435) was in scope. This was an oversight on my part during the P3.16 build — the symmetric debt formula's pattern was right there and I missed it.

- **Lease asset depreciation** (also P3.16): I introduced a Python local `lease_seed_value` (line 506) and interpolated it into the `per_quarter_dep_formula` string (line 510). Could have used a cell reference to the Q0 column of the Lease Opening Balance row.

So the asymmetry is not architectural; it's a code style inconsistency. The debt code uses cell references throughout; the lease code (which I added) uses literals for the two values it derives from Python data.

## G. Summary

**The workbook builder is consistent in its cell-reference pattern across all sheets EXCEPT for two formulas in the Capital Lease Schedule section that I added during P3.16.** Those two formulas interpolate Python literals (the per-quarter rate value and the lease seed value) directly into the Excel formula string, instead of using `local_ref(...)` to reference the corresponding row that already exists on the same sheet.

**Numerical correctness:** both formulas produce the correct value at workbook-generation time because the Python values they interpolate come from the same source as the cell-reference equivalent would. Phase 2's per-quarter rate fix DOES flow into the lease interest formula correctly (the literal becomes `0.025625` instead of `0.1025`).

**Why it matters anyway:** the workbook is intended to be an interactive Excel model. The cell-reference pattern is what makes a cell editable in Excel. The literal pattern produces formulas that look static even though they reference other rows of the model.

**Fix scope (NOT in this iter):** two one-line edits in `client_statements_output_excel/schedule_sheets.py`. No data-layer changes.
