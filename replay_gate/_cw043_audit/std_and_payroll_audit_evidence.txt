(a) THE CLOSED FORM IS THE ENGINE'S ITERATIVE CLIP - PROVEN
----------------------------------------------------------
ALGEBRA (mini's own derivation). The Layer 1 walk (finmo_model.py:541-551) is
  S0 = C = debt_closing[q];  a_i = min(r_i, S_{i-1});  S_i = S_{i-1} - a_i
with C >= 0 (Debt Schedule Closing = IF(open+new-prin < SUB_CENT, 0, ...), and
prin = MIN(open+new, ...) so the subtrahend never exceeds the balance) and every
r_i >= 0 (r_i = max(0, ...) in the engine; the workbook's Actual Debt Repayment
is MIN(open+new, MAX(0, ROUND(sched+extra,6))), also >= 0). Greedy-with-remainder
then totals exactly min(C, sum r_i): while the partial sums stay under C nothing
clips, and once they pass C the balance is exhausted and the total pins at C.

THE ONE WEDGE THAT COULD HAVE OPENED, AND WHY IT DOES NOT. The engine walks
REQUESTED repayments; the workbook cell sums the Debt sheet's ACTUAL row, which
is already clipped per quarter against open+new. So sum(actual) <= sum(requested)
and the two sides could differ if sum(actual) < C < sum(requested). They cannot:
if any quarter's actual was clipped, that quarter's real balance (which INCLUDES
issuance) fell below its requested repayment, so the issuance-free simulated
balance was already exhausted and the walk pins at C; and over that window
sum(actual) = C + sum(new) - A_end with A_end <= sum(new), so sum(actual) >= C.
Both sides are C. Equivalence holds in general.

The stub column is NOT this formula (finmo_sheet.py:368 writes the stated
cash::Short Term Debt Opening Balance at q0), so the engine's STD=0 at the stub

Liabilities carried (STD - closing) of phantom debt.
